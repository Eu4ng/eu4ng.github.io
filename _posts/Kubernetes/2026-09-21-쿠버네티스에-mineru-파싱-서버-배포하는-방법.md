PDF를 마크다운으로 바꿔 주는 **MinerU**는 공식 컨테이너 이미지가 없고 공식 Dockerfile은 NVIDIA GPU(vLLM) 전용이라, GPU가 없는 노드에서 쓸 CPU 이미지를 GitOps 저장소에서 GitHub Actions로 빌드해 GHCR에 올립니다. 클러스터가 비공개 이미지를 받을 수 있게 pull secret을 만든 뒤 매니페스트를 추가해 API 서버를 배포하고, 클러스터 안의 러너에서 파싱을 요청합니다. 워크플로우마다 MinerU와 모델을 설치하던 시간이 사라집니다.

1. 이미지 빌드
2. 이미지 pull secret 만들기
3. 매니페스트 추가
4. 배포 확인
5. GitHub Actions에서 쓰기

## 1. 이미지 빌드

GitOps 저장소에 Dockerfile과 빌드 워크플로우를 추가합니다. `python:3.12-slim`에 CPU 전용 torch와 `mineru[torch]`를 설치하고, 모델과 설정이 저장되는 경로를 `/data`로 모아 PVC로 마운트할 수 있게 합니다.

```dockerfile
# MinerU 파싱 서버(mineru-kit api-server) CPU 전용 이미지.
# 공식 Dockerfile 은 vLLM(NVIDIA) 기반이라 GPU 없는 노드에서는 쓸 수 없어 직접 만듭니다.
FROM python:3.12-slim

ARG MINERU_VERSION=4.0.5
ARG TORCH_VERSION=2.14.0

# opencv 가 libGL 과 glib 을 요구합니다.
RUN apt-get update \
 && apt-get install -y --no-install-recommends libgl1 libglib2.0-0 libgomp1 \
 && rm -rf /var/lib/apt/lists/*

ENV PIP_NO_CACHE_DIR=1 \
    PIP_ROOT_USER_ACTION=ignore

# torch 를 CPU 휠로 고정합니다. 고정하지 않으면 CUDA 휠(수 GB 의 nvidia-* 패키지)이 딸려 옵니다.
RUN pip install --extra-index-url https://download.pytorch.org/whl/cpu \
      "torch==${TORCH_VERSION}" torchvision "mineru[torch]==${MINERU_VERSION}"

# 모델과 설정은 /data 에 둡니다 (PVC 로 마운트).
ENV MINERU_HOME=/data/mineru \
    HF_HOME=/data/hf \
    MINERU_MODEL_SOURCE=huggingface \
    MINERU_MODEL_SMALL_BACKEND=torch

EXPOSE 8000
ENTRYPOINT ["mineru-kit", "api-server", "--host", "0.0.0.0", "--port", "8000"]
```

```yaml
name: build-mineru

on:
  push:
    branches: [main]
    paths: [images/mineru/**]
  workflow_dispatch:

permissions:
  contents: read
  packages: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      # 이미지 이름은 소문자여야 하고, 태그는 Dockerfile 의 MinerU 버전을 씁니다.
      - name: 이미지 이름과 태그 정하기
        id: meta
        run: |
          owner=$(echo "${{ github.repository_owner }}" | tr '[:upper:]' '[:lower:]')
          version=$(sed -n 's/^ARG MINERU_VERSION=//p' images/mineru/Dockerfile)
          echo "image=ghcr.io/$owner/mineru:$version" >> "$GITHUB_OUTPUT"

      # torch 이미지가 커서 러너 디스크를 미리 비웁니다.
      - name: 디스크 비우기
        run: sudo rm -rf /usr/share/dotnet /opt/ghc /usr/local/lib/android

      - uses: docker/setup-buildx-action@v3

      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - uses: docker/build-push-action@v6
        with:
          context: images/mineru
          push: true
          tags: ${{ steps.meta.outputs.image }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

워크플로우는 저장소의 `GITHUB_TOKEN`으로 GHCR에 로그인하므로 별도 토큰이 필요 없고, 저장소가 비공개면 이미지도 비공개 패키지로 만들어집니다. MinerU 버전을 올릴 때는 Dockerfile의 `MINERU_VERSION`만 바꾸면 새 태그로 빌드됩니다.

```bash
# 커밋하고 push
git add images .github
git commit -m "feat: MinerU CPU 이미지 빌드 워크플로우 추가"
git push
```

## 2. 이미지 pull secret 만들기

클러스터가 비공개 GHCR 이미지를 받으려면 `read:packages` 권한이 있는 토큰이 필요합니다. GHCR은 classic 토큰으로 인증하므로, GitHub 우측 상단 프로필 > **Settings** > **Developer settings** > **Personal access tokens** > **Tokens (classic)**에서 **Generate new token (classic)**을 클릭하고 **read:packages**만 선택해 발급합니다.

control plane에서 토큰을 입력받아 `mineru` 네임스페이스에 Secret을 만듭니다. 네임스페이스는 Argo CD가 만들기 전에 미리 만들어도 그대로 씁니다.

```bash
# 토큰을 입력받아 (화면에 표시되지 않음) pull secret 생성
read -rsp "GHCR 토큰: " GHCR_TOKEN; echo
kubectl create namespace mineru
kubectl create secret docker-registry ghcr-pull -n mineru \
  --docker-server=ghcr.io --docker-username=[OWNER] --docker-password="$GHCR_TOKEN"
unset GHCR_TOKEN
```

- **확인:** `kubectl get secret ghcr-pull -n mineru`에 `kubernetes.io/dockerconfigjson` 타입 Secret 표시

## 3. 매니페스트 추가

GitOps 저장소의 `services/mineru/` 폴더에 PVC, Deployment, Service를 넣습니다. 초기화 컨테이너가 모델을 PVC에 미리 받아 두므로 첫 파싱 요청이 다운로드 때문에 타임아웃되지 않습니다.

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mineru-models
  annotations:
    argocd.argoproj.io/sync-options: Prune=false   # 매니페스트를 지워도 받아 둔 모델은 남깁니다
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests:
      storage: 20Gi          # 모델 가중치와 설정(MINERU_HOME, HF_HOME)
```
{: file="services/mineru/pvc.yaml" }

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mineru
spec:
  replicas: 1                # 요청 한 건이 수 GB 를 씁니다.
  strategy:
    type: Recreate           # PVC 가 ReadWriteOnce 라 새 파드와 겹쳐 뜨면 안 됩니다
  selector:
    matchLabels: { app: mineru }
  template:
    metadata:
      labels: { app: mineru }
    spec:
      imagePullSecrets:
        - name: ghcr-pull    # 비공개 GHCR 패키지. kubectl create secret docker-registry 로 미리 만듭니다.
      # 모델은 여기서 한 번만 받아 PVC 에 둡니다. 이미 있으면 빠르게 끝납니다.
      initContainers:
        - name: download-models
          image: ghcr.io/[OWNER]/mineru:4.0.5
          command: ["mineru-kit", "models", "download", "--tier", "basic", "--small-backend", "torch"]
          volumeMounts:
            - { name: data, mountPath: /data }
      containers:
        - name: mineru
          image: ghcr.io/[OWNER]/mineru:4.0.5
          ports: [{ containerPort: 8000 }]
          volumeMounts:
            - { name: data, mountPath: /data }
          startupProbe:
            httpGet: { path: /docs, port: 8000 }
            periodSeconds: 10
            failureThreshold: 60
          readinessProbe:
            httpGet: { path: /docs, port: 8000 }
            periodSeconds: 10
          resources:
            requests: { cpu: "2", memory: 4Gi }
            limits:   { cpu: "16", memory: 16Gi }  # CPU 상한은 노드 전체. 호출한 러너는 응답을 기다리는 동안 CPU 를 쓰지 않습니다
      volumes:
        - name: data
          persistentVolumeClaim: { claimName: mineru-models }
```
{: file="services/mineru/deployment.yaml" }

```yaml
apiVersion: v1
kind: Service
metadata:
  name: mineru
spec:
  selector: { app: mineru }
  ports:
    - { port: 8000, targetPort: 8000 }
```

## 4. 배포 확인

control plane에서 파드가 이미지와 모델을 받고 `Running`이 될 때까지 지켜본 뒤, 클러스터 안에서 API가 응답하는지 임시 파드로 호출합니다. 이미지(735MB)를 받는 데 약 2분, `basic` 등급 모델(855MB)을 받는 데 약 1분이 걸려 push 후 5분 안에 `Running`이 되었습니다.

```bash
# 파드 상태 지켜보기 (Init:0/1 -> Running)
kubectl get pods -n mineru -w

# 모델 다운로드 진행 상황
kubectl logs -n mineru deploy/mineru -c download-models -f

# 서버 상태 확인
kubectl run curl --rm -it --restart=Never --image=curlimages/curl -- \
  http://mineru.mineru.svc.cluster.local:8000/v1/health
```

- **확인:** `/v1/health` 응답이 `{"status":"ok","version":"4.0.5",...}`. 파드를 지워도(`kubectl delete pod -n mineru --all`) 새 파드의 초기화 컨테이너가 모델을 다시 받지 않고 1초 만에 끝나 12초 안에 `Running`

## 5. GitHub Actions에서 쓰기

클러스터 안의 러너에서는 `http://mineru.mineru.svc.cluster.local:8000`으로 접근합니다. 러너에는 `mineru` 패키지를 torch 없이(클라이언트만) 설치하고, `mineru-kit parse`에 `--remote-url`로 서버 주소를 넘기면 파싱은 서버가 하고 결과만 받아 옵니다. 러너 이미지에는 opencv가 요구하는 `libGL`이 없으므로 `opencv-python`을 headless 판으로 바꿔 설치합니다.

```bash
# 저장소 변수에 MinerU 주소 저장
gh variable set MINERU_URL --repo [OWNER]/[REPO] \
  --body http://mineru.mineru.svc.cluster.local:8000
```

{% raw %}
```yaml
name: MinerU Test

on:
  workflow_dispatch:

jobs:
  parse:
    runs-on: arc-linux-low
    steps:
      - uses: astral-sh/setup-uv@v6
      - name: 논문 PDF 하나 내려받기
        run: curl -fsSL -o paper.pdf https://arxiv.org/pdf/1706.03762
      - name: 클라이언트 설치 (torch 없이, opencv 는 headless 로)
        run: |
          printf 'opencv-python; sys_platform == "never"\n' > override.txt
          uv tool install "mineru==4.0.5" --override override.txt --with opencv-python-headless
      - name: 클러스터 안 MinerU 서버로 파싱
        run: |
          mineru-kit parse paper.pdf -o out --tier basic --remote-url "$MINERU_URL"
          head -n 20 out/paper.md
        env:
          MINERU_URL: ${{ vars.MINERU_URL }}
```

## 마무리

공식 이미지가 없는 MinerU를 CPU 이미지로 직접 빌드해 GHCR에 올리고, GitOps로 파싱 서버를 배포해 워크플로우가 클러스터 안 주소로 파싱을 맡기는 구성을 완성했습니다. 이미지 빌드부터 배포까지 모두 저장소 push로 이루어지므로, 버전을 올릴 때도 Dockerfile과 매니페스트의 버전만 바꿔 push하면 됩니다. 실제로 논문 PDF를 위키로 바꾸는 워크플로우에서 러너 안에 MinerU를 설치하던 11분 12초가 클라이언트 설치 25초로 줄었습니다. 파싱 서버는 요청을 한 번에 하나씩 처리하므로(`--concurrency` 기본값 1), 논문 여러 편을 동시에 처리하려면 메모리를 늘리고 `command`에 `--concurrency`를 추가합니다. GPU가 없어 `basic` 등급까지만 쓸 수 있고, VLM을 쓰는 `standard` 이상은 GPU 노드가 필요합니다.
