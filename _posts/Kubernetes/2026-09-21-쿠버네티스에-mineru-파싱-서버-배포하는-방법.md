PDF를 마크다운으로 바꿔 주는 **MinerU**는 공식 컨테이너 이미지가 없고 공식 Dockerfile은 NVIDIA GPU(vLLM) 전용이라, GPU가 없는 노드에서 쓸 CPU 이미지를 GitOps 저장소에서 GitHub Actions로 빌드해 GHCR에 올립니다. 클러스터가 비공개 이미지를 받을 수 있게 pull secret을 만든 뒤 매니페스트를 추가해 API 서버 2대와 그 앞의 라우터를 배포하고, 클러스터 안의 러너에서 파싱을 요청합니다. 서버 한 대는 한 번에 한 건만 처리하므로, 라우터가 새 작업을 진행 중인 작업이 적은 서버로 보내 두 건을 동시에 처리합니다. 워크플로우마다 MinerU와 모델을 설치하던 시간이 사라집니다.

1. 이미지 빌드
2. 이미지 pull secret 만들기
3. 매니페스트 추가
4. 배포 확인
5. GitHub Actions에서 쓰기

다음 항목이 준비되어 있어야 합니다.

- Argo CD와 기본 StorageClass가 있는 클러스터 ([쿠버네티스에 Argo CD 설치하고 GitOps로 서비스 추가하는 방법](/posts/36/) 참고). 두 서버가 모델 볼륨 하나를 같이 쓰므로 StorageClass는 local-path처럼 볼륨이 한 노드에 묶이는 것이어야 합니다
- worker 노드 한 대에 메모리 20Gi(서버 2대, 서버마다 상한 10Gi)와 디스크 20Gi 이상의 여유
- 워크플로우에서 쓰려면 클러스터 안의 러너 ([쿠버네티스에 GitHub Actions Self-hosted Runner 등록하는 방법](/posts/35/) 참고)

## 1. 이미지 빌드

GitOps 저장소에 Dockerfile과 빌드 워크플로우를 추가합니다. `python:3.12-slim`에 CPU 전용 torch와 `mineru[torch]`를 설치하고, 모델과 설정이 저장되는 경로를 `/data`로 모아 PVC로 마운트할 수 있게 합니다.

```dockerfile
# MinerU 파싱 서버(mineru-kit api-server) CPU 전용 이미지.
# 공식 Dockerfile 은 vLLM(NVIDIA) 기반이라 GPU 없는 노드에서는 쓸 수 없어 직접 만듭니다.
FROM python:3.12-slim

ARG MINERU_VERSION=4.0.5
ARG TORCH_VERSION=2.14.0

# opencv 가 libGL 과 glib 을 요구합니다.
RUN apt-get update \
 && apt-get install -y --no-install-recommends libgl1 libglib2.0-0 libgomp1 \
 && rm -rf /var/lib/apt/lists/*

ENV PIP_NO_CACHE_DIR=1 \
    PIP_ROOT_USER_ACTION=ignore

# torch 를 CPU 휠로 고정합니다. 고정하지 않으면 CUDA 휠(수 GB 의 nvidia-* 패키지)이 딸려 옵니다.
RUN pip install --extra-index-url https://download.pytorch.org/whl/cpu \
      "torch==${TORCH_VERSION}" torchvision "mineru[torch]==${MINERU_VERSION}"

# 모델과 설정은 /data 에 둡니다 (PVC 로 마운트).
ENV MINERU_HOME=/data/mineru \
    HF_HOME=/data/hf \
    MINERU_MODEL_SOURCE=huggingface \
    MINERU_MODEL_SMALL_BACKEND=torch

EXPOSE 8000
ENTRYPOINT ["mineru-kit", "api-server", "--host", "0.0.0.0", "--port", "8000"]
```

## 2. 이미지 pull secret 만들기

클러스터가 비공개 GHCR 이미지를 받으려면 `read:packages` 권한이 있는 토큰이 필요합니다. GHCR은 classic 토큰으로 인증하므로, GitHub 우측 상단 프로필 > **Settings** > **Developer settings** > **Personal access tokens** > **Tokens (classic)**에서 **Generate new token (classic)**을 클릭하고 **read:packages**만 선택해 발급합니다.

control plane에서 토큰을 입력받아 `mineru` 네임스페이스에 Secret을 만듭니다. 네임스페이스는 Argo CD가 만들기 전에 미리 만들어도 그대로 씁니다.

```bash
# 토큰을 입력받아 (화면에 표시되지 않음) pull secret 생성
read -rsp "GHCR 토큰: " GHCR_TOKEN; echo
kubectl create namespace mineru
kubectl create secret docker-registry ghcr-pull -n mineru \
  --docker-server=ghcr.io --docker-username=[OWNER] --docker-password="$GHCR_TOKEN"
unset GHCR_TOKEN
```

- **확인:** `kubectl get secret ghcr-pull -n mineru`에 `kubernetes.io/dockerconfigjson` 타입 Secret 표시

## 3. 매니페스트 추가

GitOps 저장소의 `services/mineru/` 폴더에 PVC, StatefulSet, 라우터 Deployment, Service를 넣습니다. 초기화 컨테이너가 모델을 PVC에 미리 받아 두므로 첫 파싱 요청이 다운로드 때문에 타임아웃되지 않습니다. 두 서버는 모델 PVC 하나를 같이 씁니다. local-path 볼륨은 한 노드에 묶여 있어 서버들이 모두 그 노드에 뜨고, 같은 노드의 파드끼리는 `ReadWriteOnce` 볼륨을 함께 마운트할 수 있습니다.

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mineru-models
  annotations:
    argocd.argoproj.io/sync-options: Prune=false   # 매니페스트를 지워도 받아 둔 모델은 남깁니다
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests:
      storage: 20Gi          # 모델 가중치와 설정(MINERU_HOME, HF_HOME)
```
{: file="services/mineru/pvc.yaml" }

라우터가 서버를 `mineru-0`, `mineru-1` 같은 고정 이름으로 부르므로 서버는 StatefulSet으로 띄웁니다. 서버 수를 바꾸면 `router.yaml`의 `--upstream-url`도 같은 수로 맞춥니다.

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mineru
spec:
  # 서버 한 대는 한 번에 한 건만 처리합니다(--concurrency 1, 요청 한 건이 최대 7.3GiB). 여러 대를 두면 라우터(router.yaml)가
  # 작업이 적은 서버로 나눠 wiki-papers 의 논문들이 서버 수만큼 동시에 추출됩니다. 라우터가 서버를 이름(mineru-0, mineru-1 …)으로
  # 부르므로 StatefulSet 입니다. 늘리면 router.yaml 의 --upstream-url 도 같은 수로 맞춥니다.
  # 메모리: worker-1(24GiB)에 기타 약 1.1Gi + MinerU 2 × 4Gi + paper 러너(arc-linux-low 4Gi) 3개 ≈ 21Gi 요청. 실제 사용은
  # MinerU 최대 7.3GiB 두 대와 러너 0.5GiB 들이라 여기에 들어갑니다. CPU 는 두 대가 노드 24코어를 나눠 씁니다.
  replicas: 2
  serviceName: mineru-pods
  podManagementPolicy: Parallel   # 서로 기다릴 이유가 없습니다
  selector:
    matchLabels: { app: mineru }
  template:
    metadata:
      labels: { app: mineru }
    spec:
      imagePullSecrets:
        - name: ghcr-pull    # 비공개 GHCR 패키지. kubectl create secret docker-registry 로 미리 만듭니다.
      # 모델은 PVC 하나에 한 번만 받아 두고 모든 서버가 같이 씁니다. local-path(ReadWriteOnce) 볼륨은 한 노드에 묶여 있어
      # 서버들이 모두 그 노드(worker-1)에 뜨고, 같은 노드의 파드끼리는 함께 마운트할 수 있습니다. 이미 있으면 빠르게 끝납니다.
      # --tier standard: 소형 모델 + VLM(MinerU2.5-Pro 1.2B GGUF, 1.2G). wiki-papers 가 tier=advanced 로 부르는데
      # standard·advanced 가 같은 VLM 을 씁니다. basic 만 받아 두면 서버는 두 등급을 받는다고 하면서(GET /v1/tiers)
      # 가중치는 없는 상태가 됩니다. CPU 에서는 llama.cpp 엔진으로 돕니다(9쪽 논문: basic 64초, advanced 374초).
      initContainers:
        - name: download-models
          image: ghcr.io/[OWNER]/mineru:4.0.5
          command: ["mineru-kit", "models", "download", "--tier", "standard", "--small-backend", "torch"]
          volumeMounts:
            - { name: data, mountPath: /data }
      containers:
        - name: mineru
          image: ghcr.io/[OWNER]/mineru:4.0.5
          # wiki-papers 는 PDF 를 요청 본문에 담아(inline) 보냅니다. 업로드 방식은 라우터가 호출한 주소로 서버를 고정해
          # 한 러너의 논문이 늘 같은 서버로 갑니다. 본문 상한 기본 1MB 를 라우터가 알리는 파일 상한(200MB)으로 올립니다.
          args: ["--concurrency", "1", "--max-inline-bytes", "209715200"]
          ports: [{ containerPort: 8000 }]
          volumeMounts:
            - { name: data, mountPath: /data }
          # 파싱 중에는 CPU 를 다 써서 헬스체크 응답이 1초(기본값)를 넘깁니다. 준비 안 됨이 되면 headless DNS 에서 이름이
          # 빠질 수 있어 넉넉히 기다립니다. 서버가 실제로 쓸 수 있는지는 라우터가 따로 확인합니다.
          startupProbe:
            httpGet: { path: /v1/health, port: 8000 }
            periodSeconds: 10
            timeoutSeconds: 10
            failureThreshold: 60
          readinessProbe:
            httpGet: { path: /v1/health, port: 8000 }
            periodSeconds: 10
            timeoutSeconds: 10
            failureThreshold: 6
          resources:
            requests: { cpu: "2", memory: 4Gi }
            limits:   { cpu: "12", memory: 10Gi }  # 실측 최대 7.3GiB(advanced). CPU 는 두 대가 노드 24코어를 나눕니다
      volumes:
        - name: data
          persistentVolumeClaim: { claimName: mineru-models }
```

라우터는 MinerU에 들어 있는 `mineru-kit router`입니다. 서버와 같은 V1 API를 내놓고 꺼진 서버는 헬스체크로 뺍니다.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mineru-router
spec:
  replicas: 1                # 서버별 진행 중인 작업 수를 이 프로세스가 셉니다. 늘리면 한 서버에 작업이 겹칩니다
  strategy:
    type: Recreate
  selector:
    matchLabels: { app: mineru-router }
  template:
    metadata:
      labels: { app: mineru-router }
    spec:
      imagePullSecrets:
        - name: ghcr-pull
      containers:
        - name: router
          image: ghcr.io/[OWNER]/mineru:4.0.5
          # MinerU 에 들어 있는 라우터. 서버와 같은 V1 API 를 내놓고, 새 작업을 진행 중인 작업이 적은 서버로 보냅니다.
          # 꺼진 서버는 헬스체크로 빠지고, GET /v1/usage 의 limits.max_concurrent_jobs 가 살아 있는 서버의 동시 처리 수 합계입니다.
          # 클러스터 밖 서버를 더하려면 --upstream-url 을 한 줄 더 적습니다(같은 이미지·--max-inline-bytes 로 띄운 api-server).
          command:
            - mineru-kit
            - router
            - --host=0.0.0.0
            - --port=8000
            - --local-gpus=none
            - --upstream-url=http://mineru-0.mineru-pods.mineru.svc.cluster.local:8000
            - --upstream-url=http://mineru-1.mineru-pods.mineru.svc.cluster.local:8000
          ports: [{ containerPort: 8000 }]
          # 서버가 모두 죽어도 라우터는 준비 상태로 둡니다. 그래야 wiki-papers 가 usage 0 을 읽고 논문을 보류합니다.
          readinessProbe:
            httpGet: { path: /docs, port: 8000 }
            periodSeconds: 10
          resources:
            requests: { cpu: 100m, memory: 256Mi }
            limits:   { cpu: "1", memory: 1Gi }     # PDF 를 본문째 받아 서버로 넘깁니다(파일 상한 200MB)
```
{: file="services/mineru/router.yaml" }

```yaml
apiVersion: v1
kind: Service
metadata:
  name: mineru
spec:
  # 쓰는 쪽(wiki-papers 등)은 이 주소 하나만 씁니다. 라우터(router.yaml)가 받아 서버에 나눕니다.
  selector: { app: mineru-router }
  ports:
    - { port: 8000, targetPort: 8000 }
---
# 서버마다 고정 이름(mineru-0.mineru-pods …)을 주는 headless Service. 라우터가 이 이름으로 서버를 부릅니다.
# 준비 안 된 파드도 이름을 남깁니다. 바쁜 서버가 잠시 준비 안 됨이 되어 이름이 사라지면 라우터가 그 서버에서 돌고 있는
# 작업을 찾지 못합니다. 서버를 쓸 수 있는지는 라우터가 헬스체크로 판단합니다.
apiVersion: v1
kind: Service
metadata:
  name: mineru-pods
spec:
  clusterIP: None
  publishNotReadyAddresses: true
  selector: { app: mineru }
  ports:
    - { port: 8000, targetPort: 8000 }
```

## 4. 배포 확인

control plane에서 서버 두 개와 라우터가 `Running`이 될 때까지 지켜본 뒤, 클러스터 안에서 라우터가 서버 두 대를 모두 쓰고 있는지 임시 파드로 확인합니다. 첫 배포 때는 초기화 컨테이너가 이미지와 모델을 받느라 몇 분 걸리고, 모델이 PVC에 있으면 초기화 컨테이너가 2초 만에 끝납니다.

```bash
# 파드 상태 지켜보기 (mineru-0, mineru-1: Init:0/1 -> Running)
kubectl get pods -n mineru -w

# 모델 다운로드 진행 상황
kubectl logs -n mineru mineru-0 -c download-models -f

# 동시에 처리할 수 있는 작업 수 확인 (살아 있는 서버 수 x 서버당 동시 처리 수)
kubectl run curl --rm -it --restart=Never --image=curlimages/curl -- \
  http://mineru.mineru.svc.cluster.local:8000/v1/usage
```

- **확인:** `/v1/usage` 응답의 `limits.max_concurrent_jobs`가 `2`. 서버 하나가 재시작하는 동안에는 `1`

## 5. GitHub Actions에서 쓰기

클러스터 안의 러너에서는 `http://mineru.mineru.svc.cluster.local:8000`으로 접근합니다. 러너에는 `mineru` 패키지를 torch 없이(클라이언트만) 설치하고, `mineru-kit parse`에 `--remote-url`로 서버 주소를 넘기면 파싱은 서버가 하고 결과만 받아 옵니다. 러너 이미지에는 opencv가 요구하는 `libGL`이 없으므로 `opencv-python`을 headless 판으로 바꿔 설치합니다.

```bash
# 저장소 변수에 MinerU 주소 저장
gh variable set MINERU_URL --repo [OWNER]/[REPO] \
  --body http://mineru.mineru.svc.cluster.local:8000
```

> `mineru-kit parse`는 PDF를 업로드(`/v1/uploads`)로 보내는데, 라우터는 업로드를 호출한 주소로 서버를 고정합니다. 한 러너에서 보낸 파일은 다른 서버가 비어 있어도 늘 같은 서버로 갑니다. 여러 러너가 보낸 작업을 서버에 고르게 나누려면 PDF를 base64로 요청 본문에 담아(`"source": {"type": "inline", ...}`) `POST /v1/parse/jobs`로 직접 보냅니다. 서버의 `--max-inline-bytes`가 PDF 크기보다 커야 합니다. 라우터는 작업을 받는 순간 서버를 정하고 나중에 옮기지 않으므로, `GET /v1/parse/jobs?status=queued,running`의 작업 수가 `max_concurrent_jobs`보다 적을 때 제출합니다.

## 마무리

공식 이미지가 없는 MinerU를 CPU 이미지로 직접 빌드해 GHCR에 올리고, GitOps로 파싱 서버를 배포해 워크플로우가 클러스터 안 주소로 파싱을 맡기는 구성을 완성했습니다. 이미지 빌드부터 배포까지 모두 저장소 push로 이루어지므로, 버전을 올릴 때도 Dockerfile과 매니페스트의 버전만 바꿔 push하면 됩니다. 서버 한 대는 요청을 한 번에 하나씩 처리하고(`--concurrency 1`), 라우터가 서버 수만큼 동시에 나눠 처리합니다. 더 늘리려면 StatefulSet의 `replicas`와 라우터의 `--upstream-url`을 함께 늘리고, 서버마다 메모리 10Gi를 더 확보합니다. 클러스터 밖에 같은 이미지로 띄운 서버도 `--upstream-url` 한 줄로 더할 수 있습니다. GPU가 없어도 VLM을 쓰는 `standard`·`advanced` 등급이 돌지만 느립니다(9쪽 논문: `basic` 64초, `advanced` 374초).
