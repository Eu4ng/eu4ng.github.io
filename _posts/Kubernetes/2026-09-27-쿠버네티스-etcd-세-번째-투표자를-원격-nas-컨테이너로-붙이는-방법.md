control plane 이 두 대면 etcd 멤버도 두 개라 [과반](/posts/61/)이 2표 중 2표입니다. 서버 한 대가 꺼지면 남은 멤버가 과반을 잃어 API 서버가 쓰기를 멈춥니다. 그래서 control plane 을 한 대 더 두는 대신, 원격지 NAS 의 Docker(Portainer Swarm) 컨테이너에 etcd 만 띄워 세 번째 투표자로 붙입니다. 이 멤버가 멈춰도 두 control plane 끼리 과반이라 클러스터는 그대로입니다. 공식 문서는 kubeadm 으로 control plane 을 세 대 두는 방식을 권하지만, 이 글은 kubeadm 이 관리하지 않는 etcd 멤버 하나를 `etcdctl` 로 직접 추가합니다.

1. control plane peer 인증서에 NAT 주소 넣기
2. 투표자 인증서 발급
3. learner 로 멤버 추가
4. NAS 에 etcd 스택 배포
5. 투표자로 승격
6. etcd 리더 감시 두기
7. 확인

- control plane 두 대를 서로 다른 Proxmox 서버에 둔 kubeadm 클러스터 ([Proxmox에 Ansible로 kubeadm 쿠버네티스 클러스터 만드는 방법](/posts/46/))
- 두 Proxmox 노드가 Tailscale 서브넷 라우터로 집 LAN 을 광고하고(LAN → tailnet 마스커레이드 포함), NAS 의 Tailscale 이 TUN 모드인 상태 ([Proxmox 두 대를 클러스터로 묶고 원격 NAS에 QDevice 붙이는 방법](/posts/53/))
- control plane VM 이 tailnet 대역(`100.64.0.0/10`)을 자기 Proxmox 호스트로 보내는 경로. 위 kubeadm 글의 플레이북(`playbooks/k8s-cluster.yml`)이 netplan 으로 넣습니다.
- GitOps 저장소의 스택 파일을 Portainer 에 등록하는 `scripts/portainer-stack.sh` 와 그 설정 파일 ([Cloudflare Tunnel로 포트 열지 않고 홈랩 서버와 원격 NAS에 SSH 접속하는 방법](/posts/51/)의 4단계)
- 스크립트를 실행할 곳의 `ssh`(control plane 에 비밀번호 없이 sudo 할 수 있는 계정), `python3`, `openssl`

## 1. control plane peer 인증서에 NAT 주소 넣기

etcd 는 peer 연결을 받을 때 상대 인증서의 IP SAN 에 연결의 원격 주소가 있는지 봅니다. NAS 와 집 LAN 사이에는 양쪽 방향 모두 [NAT](/posts/68/) 가 끼므로, 상대가 실제로 보는 주소를 인증서에 넣어야 SAN 검사를 끄지 않고 연결됩니다.

| 연결 방향 | 받는 쪽이 보는 출발 주소 | 넣을 인증서 |
| :--- | :--- | :--- |
| NAS → control plane | Proxmox 노드의 LAN IP (서브넷 라우터가 SNAT) | 투표자 peer 인증서 (2단계) |
| control plane → NAS | Proxmox 노드의 Tailscale IP (마스커레이드) | control plane peer 인증서 (이 단계) |

kubeadm 은 control plane 의 peer 인증서 SAN 을 `ClusterConfiguration` 의 `etcd.local.peerCertSANs` 로 받습니다. 플레이북 변수에 두 Proxmox 노드의 Tailscale IP(각 노드에서 `tailscale ip -4`)를 넣고 다시 실행합니다.

```yaml
k8s_etcd_peer_sans: [[PVE01_TAILSCALE_IP], [PVE02_TAILSCALE_IP]]   # 원격 etcd 멤버(NAS)가 보는 우리 쪽 주소: Proxmox 노드의 Tailscale IP(마스커레이드)
```
{: file="group_vars/all.yml" }

```bash
# proxmox-ansible 저장소 루트에서
ansible-playbook playbooks/k8s-cluster.yml -e k8s_cluster=hub
```

플레이북은 `kubeadm-config` ConfigMap 의 `peerCertSANs` 에 주소를 더하고(나중에 합류하는 control plane 도 이 값으로 인증서를 만듭니다), 이미 있는 control plane 의 peer 인증서를 `kubeadm init phase certs etcd-peer` 로 다시 만듭니다. etcd 는 TLS 연결마다 인증서 파일을 다시 읽으므로 재시작하지 않아도 됩니다. 플레이북 없이 손으로 할 때는 아래 두 작업을 그대로 따라 합니다.

<details markdown="1">
<summary>playbooks/k8s-cluster.yml 의 peer 인증서 작업</summary>

{% raw %}
```yaml
    # 원격 etcd 멤버는 우리 쪽 연결을 NAT 뒤 주소(Proxmox 노드의 Tailscale IP)로 봅니다. 그 주소를 peer 인증서 SAN 에 넣어
    # SAN 검사를 켠 채로 연결되게 합니다. 합류하는 control plane 은 kubeadm-config 의 이 값으로 인증서를 만듭니다
    - name: etcd peer 인증서 SAN (kubeadm-config)
      ansible.builtin.shell: |
        set -e
        export KUBECONFIG=/etc/kubernetes/admin.conf
        kubectl -n kube-system get cm kubeadm-config -o jsonpath='{.data.ClusterConfiguration}' > /tmp/cluster-config.yaml
        python3 - {{ k8s_etcd_peer_sans | join(' ') }} <<'PY'
        import sys, yaml
        c = yaml.safe_load(open("/tmp/cluster-config.yaml"))
        local = c["etcd"]["local"]
        sans = local.get("peerCertSANs") or []
        add = [x for x in sys.argv[1:] if x not in sans]
        if add:
            local["peerCertSANs"] = sans + add
            yaml.safe_dump(c, open("/tmp/cluster-config.yaml", "w"), sort_keys=False)
            print("CHANGED")
        PY
        if grep -q . /tmp/cluster-config.yaml && [ -n "$(kubectl -n kube-system get cm kubeadm-config -o jsonpath='{.data.ClusterConfiguration}' | diff - /tmp/cluster-config.yaml)" ]; then
          kubectl -n kube-system create cm kubeadm-config --from-file=ClusterConfiguration=/tmp/cluster-config.yaml \
            --dry-run=client -o yaml | kubectl apply --server-side --force-conflicts -f - >/dev/null
        fi
      register: peer_sans
      changed_when: "'CHANGED' in peer_sans.stdout"
    # etcd 는 TLS 연결마다 인증서 파일을 다시 읽으므로 재시작하지 않아도 새 인증서를 씁니다
    - name: etcd peer 인증서 (이 노드)
      ansible.builtin.shell: |
        set -e
        crt=/etc/kubernetes/pki/etcd/peer.crt
        missing=""
        for ip in {{ k8s_etcd_peer_sans | join(' ') }}; do
          openssl x509 -in $crt -noout -ext subjectAltName | grep -q "IP Address:$ip\b" || missing=1
        done
        [ -z "$missing" ] && exit 0
        { printf 'apiVersion: kubeadm.k8s.io/v1beta4\nkind: InitConfiguration\nlocalAPIEndpoint:\n  advertiseAddress: %s\nnodeRegistration:\n  name: %s\n---\n' \
            {{ ansible_host }} {{ inventory_hostname }}; cat /tmp/cluster-config.yaml; } > /tmp/kubeadm-local.yaml
        mkdir -p /root/pki-backup && cp -a $crt /etc/kubernetes/pki/etcd/peer.key /root/pki-backup/
        rm $crt /etc/kubernetes/pki/etcd/peer.key
        kubeadm init phase certs etcd-peer --config /tmp/kubeadm-local.yaml
        echo CHANGED
      register: peer_cert
      changed_when: "'CHANGED' in peer_cert.stdout"
```

## 2. 투표자 인증서 발급

투표자는 클러스터와 같은 etcd CA 로 서명한 인증서를 써야 합니다. 스크립트는 control plane 에 ssh 해 그 노드의 `/etc/kubernetes/pki/etcd/ca.key` 로 서명하고, 결과만 받아 `~/.config/portainer/secrets/` 에 권한 600 으로 둡니다. CA 키는 노드 밖으로 나오지 않습니다. peer 인증서 SAN 에는 NAS 의 Tailscale IP 와 두 Proxmox 노드의 LAN IP 가, server 인증서 SAN 에는 `127.0.0.1` 과 NAS 의 Tailscale IP 가 들어갑니다. 파일 이름은 `portainer-stack.sh` 가 그대로 Swarm secret 이름으로 씁니다.

```bash
# GitOps 저장소 루트에서 스크립트 내려받기
curl -fsSL https://eu4ng.github.io/assets/scripts/kubernetes/etcd-witness-certs.sh -o scripts/etcd-witness-certs.sh

# 맨 위 "환경에 맞게 수정" 블록의 CONTROL_PLANES, WITNESS_IP, NAT_IPS 를 고친 뒤 실행 (SUFFIX v1, 클러스터 hub)
bash scripts/etcd-witness-certs.sh v1 hub
```

<details markdown="1">
<summary>scripts/etcd-witness-certs.sh 전문</summary>

```bash
#!/usr/bin/env bash
#
# 서울 NAS 의 etcd 투표자(stacks/seoul/etcd-witness, etcd-witness-<지역>)가 쓸 인증서를 그 클러스터의 etcd CA 로 발급합니다.
# 첫 control plane 에 ssh 해 그 노드의 /etc/kubernetes/pki/etcd/ca.{crt,key} 로 서명하고, 결과를 portainer-stack.sh 가 읽는
# ~/.config/portainer/secrets/ 에 둡니다(권한 600, 저장소 밖). CA 키는 노드 밖으로 나오지 않습니다.
#
# SAN 에는 투표자의 Tailscale IP 와, 투표자가 집 LAN 의 멤버에 붙을 때 거치는 NAT 주소(Tailscale 서브넷 라우터인 Proxmox 노드의
# LAN IP)를 넣습니다. etcd 는 peer 연결의 원격 주소를 상대 인증서 SAN 과 대조하므로, NAT 뒤 주소도 SAN 에 있어야 합니다.
#
# 인증서는 VALID_DAYS 동안 유효합니다. 갱신할 때는 SUFFIX 를 바꿔 다시 실행하고(Swarm secret 은 고칠 수 없어 새 이름으로 만듦)
# stack.yml 의 secret 이름을 같은 SUFFIX 로 바꿔 다시 배포합니다.
#
# 사용법: bash scripts/etcd-witness-certs.sh [SUFFIX] [CLUSTER]      (기본 SUFFIX: v1, CLUSTER: hub. 지역 엣지는 daejeon 등)

set -euo pipefail

# ---------- 환경에 맞게 수정 ----------
declare -A CONTROL_PLANES=(                         # 클러스터마다 etcd CA 가 있는 control plane
  [hub]=ubuntu@[CONTROL_PLANE_IP]
  [daejeon]=ubuntu@[EDGE_CONTROL_PLANE_IP]
)
WITNESS_IP=[NAS_TAILSCALE_IP]                       # 서울 NAS 의 Tailscale IP
NAT_IPS="[PVE01_IP] [PVE02_IP]"                     # NAS → 집 LAN 연결이 SNAT 되는 주소(서브넷 라우터의 LAN IP)
VALID_DAYS=3650
# --------------------------------------

SUFFIX=${1:-v1}
CLUSTER=${2:-hub}
CONTROL_PLANE=${CONTROL_PLANES[$CLUSTER]:?"알 수 없는 클러스터: $CLUSTER"}
PREFIX=etcd_witness$([ "$CLUSTER" = hub ] || echo "_$CLUSTER")   # Swarm secret 이름 앞부분 (허브는 etcd_witness)
OUT=$HOME/.config/portainer/secrets
log() { echo -e "\n\033[1;32m==>\033[0m $*"; }
die() { echo -e "\033[1;31m[오류]\033[0m $*" >&2; exit 1; }
trap 'echo -e "\033[1;31m[오류]\033[0m ${LINENO}번째 줄에서 중단되었습니다." >&2' ERR

names=(${PREFIX}_ca_$SUFFIX ${PREFIX}_peer_crt_$SUFFIX ${PREFIX}_peer_key_$SUFFIX ${PREFIX}_server_crt_$SUFFIX ${PREFIX}_server_key_$SUFFIX)
if [ -s "$OUT/${names[1]}" ]; then log "이미 있음: $OUT/${names[1]} (새로 만들려면 다른 SUFFIX)"; exit 0; fi
mkdir -p "$OUT" && chmod 700 "$OUT"

# ---------- 1. control plane 에서 발급 ----------
log "발급 ($CONTROL_PLANE, $VALID_DAYS 일)"
peer_sans="IP:$WITNESS_IP"; for ip in $NAT_IPS; do peer_sans="$peer_sans,IP:$ip"; done
bundle=$(ssh "$CONTROL_PLANE" "sudo -n bash -s" <<EOF
set -euo pipefail
d=\$(mktemp -d); trap 'rm -rf \$d' EXIT; cd \$d
CA=/etc/kubernetes/pki/etcd
issue() {  # \$1 이름, \$2 CN, \$3 SAN
  openssl req -new -newkey rsa:2048 -nodes -keyout \$1.key -subj "/CN=\$2" -out \$1.csr 2>/dev/null
  printf 'subjectAltName=%s\nextendedKeyUsage=serverAuth,clientAuth\nkeyUsage=critical,digitalSignature,keyEncipherment\n' "\$3" > \$1.ext
  openssl x509 -req -in \$1.csr -CA \$CA/ca.crt -CAkey \$CA/ca.key -CAcreateserial -days $VALID_DAYS -extfile \$1.ext -out \$1.crt 2>/dev/null
}
issue peer etcd-witness-$CLUSTER "$peer_sans"
issue server etcd-witness-$CLUSTER "IP:127.0.0.1,IP:$WITNESS_IP,DNS:localhost"
for f in \$CA/ca.crt peer.crt peer.key server.crt server.key; do echo "-----FILE \$(basename \$f)"; cat \$f; done
EOF
)

# ---------- 2. 파일로 저장 ----------
log "저장 → $OUT"
umask 077
BUNDLE=$bundle python3 - "$OUT" "$SUFFIX" "$PREFIX" <<'PY'
import os, sys, re
out, suffix, prefix = sys.argv[1], sys.argv[2], sys.argv[3]
data = os.environ["BUNDLE"]
parts = dict(re.findall(r"-----FILE (\S+)\n(.*?)(?=-----FILE |\Z)", data, re.S))
m = {"ca.crt": "ca", "peer.crt": "peer_crt", "peer.key": "peer_key", "server.crt": "server_crt", "server.key": "server_key"}
for src, dst in m.items():
    path = f"{out}/{prefix}_{dst}_{suffix}"
    open(path, "w").write(parts[src])
    print("   ", path)
PY
openssl x509 -in "$OUT/${PREFIX}_peer_crt_$SUFFIX" -noout -subject -enddate -ext subjectAltName | sed 's/^/    /'
log "완료. stack.yml 의 secret 이름(${PREFIX}_*_$SUFFIX)을 확인하고 bash scripts/portainer-stack.sh stacks/seoul/etcd-witness$([ "$CLUSTER" = hub ] || echo "-$CLUSTER")/stack.yml 로 배포합니다."
```
{: file="scripts/etcd-witness-certs.sh" }

</details>

## 3. learner 로 멤버 추가

바로 투표 멤버로 추가하면 멤버가 셋이 되어 과반이 2표가 되는데, NAS 의 etcd 가 아직 뜨지 않은 동안 서버 한 대가 죽으면 과반을 잃습니다. 그래서 투표권이 없는 learner 로 먼저 추가하고, 데이터를 따라잡은 뒤 5단계에서 승격합니다.

```bash
# control plane 에서. etcd 파드 이름은 etcd-<노드 이름>
ETCDCTL="kubectl -n kube-system exec etcd-k8s-hub-cp-1 -- etcdctl --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt --cert=/etc/kubernetes/pki/etcd/server.crt --key=/etc/kubernetes/pki/etcd/server.key"

$ETCDCTL member add etcd-witness --learner --peer-urls=https://[NAS_TAILSCALE_IP]:2380
```

출력의 `ETCD_INITIAL_CLUSTER` 값이 다음 단계 스택 파일의 `--initial-cluster` 에 들어갑니다. 멤버 이름은 control plane 노드 이름입니다.

```text
Member [MEMBER_ID] added to cluster [CLUSTER_ID]

ETCD_NAME="etcd-witness"
ETCD_INITIAL_CLUSTER="k8s-hub-cp-1=https://[CP1_IP]:2380,k8s-hub-cp-2=https://[CP2_IP]:2380,etcd-witness=https://[NAS_TAILSCALE_IP]:2380"
ETCD_INITIAL_ADVERTISE_PEER_URLS="https://[NAS_TAILSCALE_IP]:2380"
ETCD_INITIAL_CLUSTER_STATE="existing"
```

- **확인:** `$ETCDCTL member list -w table` 에 새 멤버가 `unstarted`(이름은 아직 비어 있음), `IS LEARNER` 가 `true` 로 보입니다.

## 4. NAS 에 etcd 스택 배포

NAS 에서는 kubeadm 과 같은 etcd 이미지를 씁니다. control plane 에서 `sudo grep image: /etc/kubernetes/manifests/etcd.yaml` 로 버전을 확인해 `image` 에 넣습니다. peer·client 포트는 NAS 의 Tailscale IP 에만 열어 NAS 의 LAN 에는 드러나지 않게 하고, Swarm 은 `network_mode: host` 를 무시하므로 `host` 네트워크를 외부 네트워크로 붙입니다. `--initial-cluster` 는 데이터 폴더가 비어 있는 첫 기동에만 쓰입니다.

`--election-timeout=50000` 은 이 멤버가 리더로 뽑히지 않게 하려는 값입니다. etcd 에는 투표만 하고 리더는 되지 못하는 역할이 없어서, NAS 멤버만 선거에 나서기까지 기다리는 시간을 etcd 상한(50초)으로 두어 LAN 의 control plane 멤버(기본 1초)가 항상 먼저 나서게 합니다. 이 값을 주기 전에 NAS 멤버가 리더로 뽑힌 적이 있습니다. 인터넷 구간 손실로 쓰기가 시간 초과되어 kube-vip 가 리스를 갱신하지 못했고, 엣지 클러스터의 API·서비스 VIP 가 약 24분 동안 내려갔습니다. etcd 문서는 선거 타임아웃을 모든 멤버가 같게 두라고 하므로([etcd와 Raft 합의 알고리즘의 동작 원리](/posts/61/)), 이 멤버만 다르게 둔 것은 그 권고에서 벗어난 선택입니다. 그래도 리더로 뽑혔을 때를 대비한 안전망이 스택 파일 주석의 `etcd-leader-guard` 이고, 6단계에서 control plane 에 둡니다.

```yaml
# 원격지 NAS(Synology, Portainer Swarm)의 etcd 투표자. 쿠버네티스 etcd 는 control plane 두 대에 하나씩 있어,
# 세 번째 멤버를 여기 두어 어느 서버가 죽어도 과반(3표 중 2표)이 남게 합니다. 이 멤버가 멈춰도 두 control plane 끼리 과반입니다.
# kubeadm 이 관리하지 않는 멤버입니다. 쿠버네티스를 올릴 때 kubeadm 의 etcd 버전(/etc/kubernetes/manifests/etcd.yaml)과 같게 image 를 바꿉니다.
# NAS 의 Tailscale(TUN 모드)로 집 LAN 과 연결되고, NAS 의 Tailscale IP 에만 엽니다.
# --initial-cluster 는 데이터가 비어 있을 때(처음 한 번)만 씁니다. member add 출력의 ETCD_INITIAL_CLUSTER 와 같아야 합니다.
version: "3.8"
services:
  etcd:
    image: registry.k8s.io/etcd:3.7.0-0
    command:
      - etcd
      - --name=etcd-witness
      - --data-dir=/var/lib/etcd
      - --initial-cluster=k8s-hub-cp-1=https://[CP1_IP]:2380,k8s-hub-cp-2=https://[CP2_IP]:2380,etcd-witness=https://[NAS_TAILSCALE_IP]:2380
      - --initial-cluster-state=existing
      - --initial-advertise-peer-urls=https://[NAS_TAILSCALE_IP]:2380
      - --listen-peer-urls=https://[NAS_TAILSCALE_IP]:2380
      - --advertise-client-urls=https://[NAS_TAILSCALE_IP]:2379
      - --listen-client-urls=https://127.0.0.1:2379,https://[NAS_TAILSCALE_IP]:2379
      - --listen-metrics-urls=http://127.0.0.1:2381
      - --client-cert-auth=true
      - --peer-client-cert-auth=true
      - --trusted-ca-file=/run/secrets/etcd_witness_ca_v1
      - --peer-trusted-ca-file=/run/secrets/etcd_witness_ca_v1
      - --cert-file=/run/secrets/etcd_witness_server_crt_v1
      - --key-file=/run/secrets/etcd_witness_server_key_v1
      - --peer-cert-file=/run/secrets/etcd_witness_peer_crt_v1
      - --peer-key-file=/run/secrets/etcd_witness_peer_key_v1
      - --snapshot-count=10000
      # 이 멤버는 표만 보태고 리더가 되면 안 됩니다(인터넷 건너편이라 리더가 되면 쓰기가 느려지거나 멈춥니다). etcd 에는 리더를 막는
      # 설정이 없어, 리더가 사라졌을 때 선거에 나서기까지 기다리는 시간을 허용 최대값(50초)으로 둡니다. LAN 멤버(기본 1초)가 항상 먼저
      # 나서서 이 멤버의 표를 받아 리더가 됩니다. 그래도 리더가 되면 control plane 의 감시(proxmox-ansible etcd-leader-guard)가 되돌립니다.
      - --election-timeout=50000
    secrets:
      - etcd_witness_ca_v1
      - etcd_witness_server_crt_v1
      - etcd_witness_server_key_v1
      - etcd_witness_peer_crt_v1
      - etcd_witness_peer_key_v1
    volumes:
      - etcd-witness-data:/var/lib/etcd
    networks:
      - hostnet               # Swarm 은 network_mode: host 를 무시하므로 호스트 네트워크에 붙입니다
    deploy:
      replicas: 1
      restart_policy:
        condition: any

secrets:                      # scripts/etcd-witness-certs.sh 가 만든 파일로 portainer-stack.sh 가 만듭니다. 갱신은 새 이름(_v2)으로
  etcd_witness_ca_v1: { external: true }
  etcd_witness_server_crt_v1: { external: true }
  etcd_witness_server_key_v1: { external: true }
  etcd_witness_peer_crt_v1: { external: true }
  etcd_witness_peer_key_v1: { external: true }

volumes:
  etcd-witness-data:

networks:
  hostnet:
    external: true
    name: host
```
{: file="stacks/[REGION]/etcd-witness/stack.yml" }

## 5. 투표자로 승격

learner 가 leader 의 데이터를 따라잡아야 승격됩니다. 아직이면 `can only promote a learner member which is in sync with leader` 로 거부되므로 잠시 뒤 다시 실행합니다.

```bash
# control plane 에서. [MEMBER_ID] 는 member list 의 ID
$ETCDCTL member promote [MEMBER_ID]
```

- **확인:** `Member [MEMBER_ID] promoted in cluster [CLUSTER_ID]` 가 출력되고, `$ETCDCTL member list -w table` 의 `IS LEARNER` 가 세 멤버 모두 `false` 입니다.

## 6. etcd 리더 감시 두기

선거 대기 시간을 길게 둔 것만으로는 NAS 멤버가 리더가 되는 일을 완전히 막지 못합니다. 그래서 control plane 마다 감시 서비스를 두어, 리더가 원격 투표자로 넘어가면 자기 노드로 되돌립니다. 스크립트는 30초마다 자기 노드 etcd 의 HTTP API 로 리더를 확인하고, 리더의 이름이 `etcd-witness` 로 시작하면 그 멤버에게 리더를 자기 노드로 넘기라고 요청합니다. API 서버가 멈춰도 돌아야 하므로 쿠버네티스 파드가 아니라 노드의 systemd 서비스로 두고, 노드에 `etcdctl` 이 없어 `curl` 과 `jq` 로 부릅니다. 인증서는 kubeadm 이 만든 `/etc/kubernetes/pki/etcd/healthcheck-client.crt` 를 씁니다.

설치는 [클러스터 플레이북](/posts/46/)의 `etcd 리더 감시` 플레이가 합니다. 스크립트를 `proxmox-ansible` 저장소의 `scripts/` 에 두고 플레이북을 다시 실행합니다.

```bash
# proxmox-ansible 저장소에서. 스크립트 내려받기
mkdir -p scripts
curl -fsSL https://eu4ng.github.io/assets/scripts/proxmox/etcd-leader-guard.sh -o scripts/etcd-leader-guard.sh

# control plane 마다 /usr/local/sbin/etcd-leader-guard 와 etcd-leader-guard.service 를 둡니다
ansible-playbook playbooks/k8s-cluster.yml -e k8s_cluster=hub
```

<details markdown="1">
<summary>scripts/etcd-leader-guard.sh 전문</summary>

```bash
#!/usr/bin/env bash
#
# etcd 리더가 원격 투표자(etcd-witness*, 서울 NAS)이면 이 노드로 리더를 옮깁니다. control plane 노드마다 서비스로 돕니다
# (playbooks/k8s-cluster.yml 이 설치). 원격 투표자는 표만 보태는 멤버인데 etcd 에는 리더가 되지 못하게 하는 설정이 없습니다.
# 선거 대기 시간을 최대값으로 둔 것(k8s-gitops stacks/seoul/etcd-witness*)이 뚫렸을 때의 안전망입니다.
# API 서버가 멈춰도 돌아야 하므로 쿠버네티스 밖에서, etcd 의 HTTP API 를 curl 로 부릅니다(노드에 etcdctl 이 없음).
#
# 사용법: etcd-leader-guard.sh [--once]      --once 는 한 번만 확인하고 끝냅니다. 없으면 INTERVAL 초마다 반복합니다.
# 필요: curl, jq, /etc/kubernetes/pki/etcd 의 인증서(root)

set -uo pipefail

PKI=${PKI:-/etc/kubernetes/pki/etcd}
LOCAL=${LOCAL:-https://127.0.0.1:2379}
WITNESS_PREFIX=${WITNESS_PREFIX:-etcd-witness}
INTERVAL=${INTERVAL:-30}

api() {  # URL, 본문, [시간 제한(초)]
  curl -sS --fail -m "${3:-5}" --cacert "$PKI/ca.crt" --cert "$PKI/healthcheck-client.crt" --key "$PKI/healthcheck-client.key" \
    -X POST "$1" -d "$2"
}

check() {
  local status leader me members name url
  status=$(api "$LOCAL/v3/maintenance/status" '{}' 2>/dev/null) || return 0   # 이 노드의 etcd 가 응답하지 않으면 할 일이 없음
  leader=$(jq -r '.leader // "0"' <<<"$status")
  me=$(jq -r '.header.member_id' <<<"$status")
  [ "$leader" != 0 ] && [ "$leader" != "$me" ] || return 0                     # 리더가 없거나(선거 중) 이 노드가 리더
  # linearizable=false: 리더가 멈춰 있어도 이 노드가 아는 멤버 목록으로 답합니다
  members=$(api "$LOCAL/v3/cluster/member/list" '{"linearizable":false}') || return 1
  name=$(jq -r --arg id "$leader" '.members[] | select(.ID == $id) | .name' <<<"$members")
  case "$name" in "$WITNESS_PREFIX"*) ;; *) return 0 ;; esac
  url=$(jq -r --arg id "$leader" '.members[] | select(.ID == $id) | .clientURLs[0]' <<<"$members")
  echo "리더가 원격 투표자 $name 입니다. 이 노드로 옮깁니다."
  # 리더를 옮기는 요청은 지금 리더가 받아야 합니다. 다른 control plane 이 먼저 옮겼으면 실패하지만 다음 확인에서 걸러집니다
  if api "$url/v3/maintenance/transfer-leadership" "{\"targetID\":\"$me\"}" 20 >/dev/null; then
    echo "리더를 옮겼습니다."
  else
    echo "리더를 옮기지 못했습니다. 다음 확인 때 다시 시도합니다." >&2
    return 1
  fi
}

if [ "${1:-}" = --once ]; then
  check
  exit
fi
while true; do
  check || true
  sleep "$INTERVAL"
done
```

## 트러블슈팅

<details markdown="1">
<summary>learner 가 <code>started</code> 가 되지 않고 etcd 로그에 <code>rejected connection</code> 이 보임</summary>

- **원인:** peer 연결의 원격 주소가 상대 인증서의 IP SAN 에 없습니다. NAS 쪽 로그에서 거부되면 control plane 인증서에 Proxmox 노드의 Tailscale IP 가, control plane 쪽 로그에서 거부되면 투표자 인증서에 Proxmox 노드의 LAN IP 가 빠진 것입니다.
- **해결:** 빠진 쪽에 따라 1단계를 다시 실행하거나, 2단계를 새 SUFFIX 로 다시 실행해 스택의 secret 이름을 바꾸고 다시 배포합니다. 거부 로그에 함께 찍히는 원격 주소가 인증서에 넣어야 할 주소입니다.

</details>

## 마무리

control plane 두 대와 원격 NAS 의 etcd 컨테이너로 투표 멤버 셋을 만들었습니다. 어느 서버 한 대가 꺼져도 남은 control plane 과 NAS 멤버로 과반이 유지되고, NAS 와의 연결이 끊겨도 두 control plane 끼리 과반입니다. 다만 두 서버가 모두 꺼지면 NAS 멤버 혼자서는 클러스터를 돌릴 수 없습니다.
