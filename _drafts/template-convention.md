- 본문 제목은 H2 만 씁니다. Chirpy 에서는 H2 와 H3 가 거의 같은 크기로 보여 섞어 쓰면 구분되지 않습니다.
- 첫 문단은 제목 없이 씁니다. description 이 글 제목 아래에 이미 표시되므로 같은 말을 반복하지 않습니다.
- 규칙 항목은 "## 1. 항목" 형식이며, 번호가 중복되지 않았는지 마지막에 점검합니다.
- H3 이하는 쓰지 않습니다. 더 나눠야 하면 규칙 항목을 쪼개거나 안내 문장, 목록, 표로 잇습니다.

규칙 작성 원칙
- 규칙 한 줄은 "~한다", "~하지 않는다" 로 끝나는 단정문이거나 개조식으로 씁니다. "가급적", "되도록" 은 피합니다.
- 모든 규칙에 이유를 붙입니다. 이유를 댈 수 없는 규칙은 넣지 않습니다.
- 좋은 예와 나쁜 예를 짝지어 보여 줍니다. 예시는 실제로 쓸 법한 것으로 고릅니다.

문체와 강조
- 설명 문장은 합니다체, 규칙과 목록 항목은 개조식으로 씁니다.
- 굵은 글씨는 설정 라벨과 핵심 용어의 첫 등장에만 씁니다.
- 식별자, 설정 키, 설정값은 인라인 코드로 씁니다.

코드
- 형식이나 예시를 보여 주는 블록은 text, 설정 파일은 yaml 또는 json, 실행 명령은 bash

규칙이 왜 필요했는지, 규칙이 없을 때 어떤 문제가 있었는지 두세 문장으로 적습니다.

- **적용 범위:** 어떤 프로젝트, 어떤 파일, 어떤 상황에 적용하는지
- **기준:** 어떤 표준이나 공식 문서를 바탕으로 했는지

## 요약

> - 핵심 규칙 하나
> - 핵심 규칙 둘
> - 핵심 규칙 셋
{: .prompt-tip }

## 1. 항목 이름

- **규칙:** 무엇을 어떻게 하는지 한 줄로 작성
- **이유:** 이 규칙이 막아 주는 문제나 얻는 이점

```text
# 좋은 예
feat(player): add double jump

# 나쁜 예
Update code
```

## 2. 항목 이름

값이 여러 개인 규칙은 표로 정리합니다.

| 대상 | 형식 | 예시 |
| :--- | :--- | :--- |
| 파일 | `lower-case` | `check-dist.yml` |
| 변수 | `PascalCase` | `MaxHealth` |

- **이유:** 이 규칙이 막아 주는 문제나 얻는 이점

## 권장 설정 (선택)

설정 화면의 메뉴 구조를 그대로 따라 중첩 목록으로 적습니다.

- **설정** > **리포지토리**
  - **보호된 브랜치**
    - **머지 허용:** `Maintainers`
    - **푸시 허용:** `No one`
  - **이유:** 이렇게 설정하는 까닭

## 적용 방법 (선택)

규칙을 사람의 기억에 맡기지 않고 도구로 강제하는 방법을 적습니다.

```json
{
  "extends": ["[CONFIG_NAME]"]
}
```
{: file=".commitlintrc.json" }

설치 과정이 길다면 별도의 방법 글로 분리하고 [글 제목](/posts/N/) 링크만 남깁니다.

## 예외 (선택)

- 규칙을 지키지 않아도 되는 경우와 그 이유
- 아직 정하지 못해 보류한 항목
